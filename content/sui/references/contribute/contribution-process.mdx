The Sui documentation is open source and thrives on community contributions. Whether you’re fixing a typo, clarifying explanations, or adding entirely new content, your work benefits the whole community. You can contribute to the documentation using either GitHub’s web editor or your local development environment.

## Follow the style guide

All documentation changes must follow the [Sui style guide](/references/contribute/style-guide). Reviewers provide feedback to ensure consistency in tone and quality. Don’t be discouraged if your pull request (PR) receives multiple review comments, as this process helps maintain clarity and uniformity across all docs. After your PR merges, future updates might refine your content further.

When writing, keep these key principles in mind:

- Use active voice.  
- Write in present tense.  
- Be clear and concise. Use only as many words as needed.  

## GitHub web editor

If you’re new to Git or prefer a more basic workflow, you can make small edits directly in GitHub’s web interface.

- **Add a new page**
  1. Fork the [Sui documentation repository](https://github.com/MystenLabs/sui-docs) if you do not already have a fork.
  1. In your fork, open the relevant subdirectory under `content/sui`.
  1. Click **Add file**, then **Create new file**.
  1. Name your file with the `.mdx` extension and write your content.
- **Edit an existing page**
  1. Click **Edit this page** at the bottom of the published documentation page to open its source on GitHub. If you are already in the repository, open the file under `content/sui` and click **Edit this file**.
  1. Make your edits.

Commit the changes to a branch on your fork, then open a PR.

## Set up a local environment {#local-environment}

For larger changes, fork [MystenLabs/sui-docs](https://github.com/MystenLabs/sui-docs), clone your fork, and create a branch based on `main`. See the [repository build instructions](https://github.com/MystenLabs/sui-docs#building) for prerequisites and details about fetching sources from other repositories.

1. Edit or add `.mdx` files under `content/sui`.
1. From the root of your clone, switch to `sites/sui`, install dependencies, and start the local development server.

   ```bash
   $ cd sites/sui
   $ pnpm install
   $ pnpm start
   ```

1. Open `http://localhost:3000` and verify that your page renders and its links work.
1. Commit the edited files and push your branch to your fork.

## Review process {#review-process}

1. Open a PR against the `main` branch of [MystenLabs/sui-docs](https://github.com/MystenLabs/sui-docs). Describe the change and how you verified it. Link any related issues.
1. If the PR includes a Vercel preview, use it to verify your changes on the rendered site.
1. Reviewers provide feedback. It’s your responsibility to update your PR based on their comments. Multiple reviewers might give input.
1. Approved changes appear on the documentation site after the PR merges and the site deploys.
