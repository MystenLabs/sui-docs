Sui releases new versions of each network on a consistent schedule and announces each release through official channels. To keep your full node in sync with the network, update it with each release.

## When does Sui release new versions? {#sui-release-process}

Sui deploys each network on a consistent schedule. Extenuating circumstances might delay releases occasionally, but these delays are rare, and Sui communicates them through [official channels](#communication).

- `devnet`: Deployed every week on Mondays.
- `testnet`: Deployed every week on Tuesdays.
- `mainnet`: Deployed every two weeks on Wednesdays.

:::info

For additional details, see each network's [release schedule and configuration](https://sui.io/networkinfo).

:::

Whenever Sui releases a new version, you must update your full node with the release to ensure compatibility with the network it connects to. For example, if you use Sui Testnet you should install the version of Sui running on Sui Testnet.

You must apply any release that contains a protocol change before the protocol upgrade takes place. Validators enact protocol upgrades: when enough stake within the validator set upgrades, the new protocol version takes effect in the next epoch. Full nodes do not take part in that vote, but they must run a compatible release.
If you do not update your full node, it cannot connect to the network after the protocol upgrade takes place.

## Communication

Sui announces releases on the [Sui Discord server](https://discord.com/invite/sui) and the [node-operators](https://groups.google.com/a/groups.sui.io/g/node-operators) Google group.

## How do I update my full node? {#update-your-full-node}

You can track the latest version of Sui on the [Sui Releases](https://github.com/MystenLabs/sui/releases) page on GitHub.
The schedule for each network is available in the [Network Release Schedule](https://sui.io/networkinfo) page.

It is reasonable to have to shut down your full node to perform an update, whether that be a rolling restart in Kubernetes, or a systemctl stop on a Linux machine to replace the sui-node binary. After the restart, check the version your node reports against the latest version on the [Sui Releases](https://github.com/MystenLabs/sui/releases) page on GitHub to confirm the update applied.
