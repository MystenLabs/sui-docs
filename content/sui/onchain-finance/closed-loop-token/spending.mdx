[Closed-Loop Tokens](/onchain-finance/closed-loop-token) differ from standard `Coin` types in a key way: `Token` types do not have the `store` ability. This means you cannot store a `Token` inside another object or add it to a balance field the way you can with a `Coin`. An application that accepts a `Token` as payment cannot keep it.

To handle this, `Token` provides a `spend` method. When you call `spend`, the method consumes the token and moves its balance into an [`ActionRequest`](/onchain-finance/closed-loop-token/action-request). You then deliver the `ActionRequest` to the [`TokenPolicy`](/onchain-finance/closed-loop-token/token-policy) (which accumulates the spent balance) or burn it directly with a `TreasuryCap`.

## How do I spend a token?

To spend a token, call the `spend` method. It takes the following arguments:

```move
// module sui::token
public fun spend<T>(token: Token<T>, ctx: &mut TxContext): ActionRequest<T>;
```

The `sui::token` module defines the `spend` function, along with the `Token` and `ActionRequest` types and the `add_approval` function, which the [gift shop example](#how-do-i-gate-the-spend-action) uses.

As the signature shows, `spend` consumes the `Token` object. Its balance becomes the `spent_balance` in the [`ActionRequest`](/onchain-finance/closed-loop-token/action-request).

## What happens to a spent token?

The `ActionRequest` for the `spend` action contains the `Balance` of the spent `Token`, and you can either confirm it [with a `TreasuryCap`](/onchain-finance/closed-loop-token/action-request) or [deliver it to the `TokenPolicy`](/onchain-finance/closed-loop-token/action-request). In the first case, you burn the balance directly with the `TreasuryCap`. In the second case, the balance moves to the `TokenPolicy` `spent_balance`.

You cannot use spent balance in any way, and you cannot withdraw it. The only available action is [flushing](/onchain-finance/closed-loop-token/token-policy#how-do-i-consume-a-spent-token-balance): burning the `spent_balance` by bringing a `TreasuryCap`.


## How do I gate the spend action?

Normally, assign at least one rule to the `spend` action to prevent aimless spending. The recommended way to authorize the spend in an application that accepts the token is to stamp it right in the function that performs the spend. Stamping means calling `token::add_approval` with a rule-like witness (here `GiftShop {}`), which adds an approval to the `ActionRequest` recording that the rule performed the action. For example:

```move
/// Rule-like witness to stamp the ActionRequest
public struct GiftShop has drop {}

/// Spend the token and return a Gift + ActionRequest
public fun buy_gift(
    token: Token<CREDITS>,
    ctx: &mut TxContext
): (Gift, ActionRequest<CREDITS>) {

    // token is spent
    let action_request = token::spend(token, ctx);

    // stamp the ActionRequest as performed by GiftShop
    token::add_approval(GiftShop {}, &mut action_request, ctx);

    // return already stamped ActionRequest
    (Gift { ... }, action_request)
}
```

The caller of `buy_gift` keeps the `Gift` and must still confirm the returned `ActionRequest`, either [with a `TreasuryCap`](/onchain-finance/closed-loop-token/action-request) or by [delivering it to the `TokenPolicy`](/onchain-finance/closed-loop-token/action-request), as [What happens to a spent token?](#what-happens-to-a-spent-token) explains.
