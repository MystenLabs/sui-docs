Pyth on Sui is a pull oracle: the consumer pulls the price update it needs into its own transaction. Your client fetches a fresh signed update offchain, then a single transaction applies it onchain and reads it, in that order. This walkthrough reads a Pyth feed end to end on Testnet.

:::caution

The `examples/oracle-adapter` samples pin version 2 of the Pyth Sui SDK (`@pythnetwork/pyth-sui-js`), which takes the legacy `SuiClient` from `@mysten/sui` version 1. Current Sui full nodes do not serve the API that client calls, so the samples fail against them. Version 4 of the Pyth Sui SDK accepts any `@mysten/sui` version 2 client that exposes the `.core` API, so pass a `SuiGrpcClient` to `SuiPythClient` instead. Version 4 declares `@mysten/sui` `^2.7.0` as its peer dependency, so pair it with `@mysten/sui` 2.x until Pyth publishes a release for `@mysten/sui` 3.0. The `SuiPythClient` and `SuiPriceServiceConnection` methods the samples call keep the same signatures in version 4. The `checkStale` sample also calls `devInspectTransactionBlock`. On `SuiGrpcClient`, use `simulateTransaction` instead.

:::

The TypeScript samples live in the `examples/oracle-adapter/ts` package and type-check with `tsc --noEmit`:

```sh

tsc --noEmit
```

## How do I update and read a Pyth price in one transaction?

To update and read a Pyth price in one transaction:

1. Fetch the latest update for your feed from Hermes.
2. Apply it with `updatePriceFeeds`. It appends the verify and update commands and returns the object IDs to read.
3. Read the returned `PriceInfoObject` in the same transaction.

The price comes back as an integer magnitude and a signed exponent, and the exponent is typically negative. The price is magnitude × 10^exponent. For example, a magnitude of `68005477` at exponent `-8` is `68005477` × 10^-8 = `0.68005477`, about `0.68` USD. Judge the confidence interval relative to the price.

<ImportContent source="examples/oracle-adapter/ts/src/read.ts" mode="code" tag="update-read" />

**Observe:** the transaction succeeds and the read returns a current price. Running this against Testnet for `SUI/USD` returns a price near the live market rate, with a confidence interval around `0.1%` of the price. The `68005477` magnitude in the example is illustrative only, because the market price changes between runs. The read goes through the adapter's staleness bound, so a price the update failed to refresh aborts rather than reading old.

## Paying for a Pyth price update

`updatePriceFeeds` takes only the transaction, the update data from Hermes, and the feed IDs. The samples pass no separate fee coin to it. A transaction that applies an update costs gas plus the Pyth base update fee, so fund the sender address with Testnet SUI before running the update-and-read sample and plan the sender's funds and gas budget for both. The keeper sample sets an explicit gas budget after it appends the update commands:

```typescript
	await pyth.updatePriceFeeds(tx, updates, [feedId]);
	tx.setGasBudget(150_000_000n);
```

## What happens when a price feed is stale?

A price that nobody has updated recently is stale. Reading it with a tight maximum age aborts with the provider's staleness error rather than returning an old value. This is `dev-inspect`-able, so you can confirm the rejection without spending gas or updating the feed:

<ImportContent source="examples/oracle-adapter/ts/src/read.ts" mode="code" tag="stale-read" />

The preceding sample is the exported `checkStale` function, a separate code path from the update-and-read flow. It never applies an update. It looks up the feed's existing `PriceInfoObject`, calls the Pyth staleness-checked reader with your `maxAgeSecs`, and runs the transaction as a read-only simulation. It returns an object with the simulation `status` and, when the read aborts, the `error` string. It throws `no PriceInfoObject for feed` followed by the feed ID if the feed has no onchain object.

**Observe:** with a one-second bound on a feed nobody just updated, the call fails with a `MoveAbort` in `pyth::check_price_is_fresh` (error code `3`, stale price). This is the single most important behavior for a high-stakes consumer to rely on. [Oracle safety](/onchain-finance/oracles/oracle-safety) covers it in depth.
