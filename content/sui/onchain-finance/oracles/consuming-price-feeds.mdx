Both Pyth and Switchboard on Sui are pull oracles: the consumer pulls the price update it needs into its own transaction. Your client fetches a fresh signed update offchain, then a single transaction applies it onchain and reads it, in that order. This walkthrough reads a Pyth feed end to end on Testnet, then shows the Switchboard on-demand variant.

:::caution

The Pyth Sui SDK talks JSON-RPC, but the Mysten Testnet full node serves gRPC, so the default `getFullnodeUrl('testnet')` returns 404 for every SDK call. Point `rpcUrl` at a JSON-RPC provider or your own node. Every Testnet Pyth consumer hits this, and the failure looks like an unrelated 404 rather than an RPC-protocol mismatch. For the same reason, these samples use a JSON-RPC client rather than the `SuiGrpcClient` that the rest of this documentation uses.

:::

The TypeScript samples live in the `examples/oracle-adapter/ts` package and type-check with `tsc --noEmit`:

```sh
cd examples/oracle-adapter/ts
tsc --noEmit
```

They pin the network's package and object IDs in a config module rather than inline, so a rotated ID is a one-line change:

The config's Pyth and Wormhole state object IDs and the Hermes endpoint come from the [Pyth Sui addresses](https://docs.pyth.network/price-feeds/contract-addresses/sui); its feed IDs come from the [Pyth feed list](https://pyth.network/developers/price-feed-ids). If a call fails because an ID is wrong or has rotated, check it against those pages and update the config module.

## How do I update and read a Pyth price in one transaction?

To update and read a Pyth price in one transaction:

1. Fetch the latest update for your feed from Hermes.
2. Apply it with `updatePriceFeeds`. It appends the verify and update commands and returns the object IDs to read.
3. Read the returned `PriceInfoObject` in the same transaction.

The price comes back as an integer magnitude and a signed exponent, and the exponent is typically negative. The price is magnitude × 10^exponent. For example, a magnitude of `68005477` at exponent `-8` is `68005477` × 10^-8 = `0.68005477`, about `0.68` USD. Judge the confidence interval relative to the price.

<ImportContent source="examples/oracle-adapter/ts/src/read.ts" mode="code" tag="update-read" />

**Observe:** the transaction succeeds and the read returns a current price. Running this against Testnet for `SUI/USD` returns a price near the live market rate, with a confidence interval around `0.1%` of the price. The `68005477` magnitude in the example is illustrative only, because the market price changes between runs. The read goes through the adapter's staleness bound, so a price the update failed to refresh aborts rather than reading old.

## What happens when a price feed is stale?

A price that nobody has updated recently is stale. Reading it with a tight maximum age aborts with the provider's staleness error rather than returning an old value. This is `dev-inspect`-able, so you can confirm the rejection without spending gas or updating the feed:

<ImportContent source="examples/oracle-adapter/ts/src/read.ts" mode="code" tag="stale-read" />

**Observe:** with a one-second bound on a feed nobody just updated, the call fails with a `MoveAbort` in `pyth::check_price_is_fresh` (error code `3`, stale price). This is the single most important behavior for a high-stakes consumer to rely on. [Oracle safety](/onchain-finance/oracles/oracle-safety) covers it in depth.

Switchboard's `current_result` does not gate on age, so there is no equivalent staleness abort to dev-inspect; your consumer checks the timestamps itself, as the Switchboard section of this page describes.

## How do I read a Switchboard feed on Sui?

Switchboard is also pull, with a different shape. Instead of a shared price object you update, you hold an `Aggregator` feed and pull a fresh oracle response into your transaction with `fetchUpdateTx`, which must be the first action in the [programmable transaction block (PTB)](/develop/transactions/ptbs/prog-txn-blocks). A PTB runs its commands in order within one transaction, so the fresh response lands before your consumer reads it. Your Move consumer then reads `switchboard::aggregator::current_result`.

<ImportContent source="examples/oracle-adapter/ts/src/switchboard.ts" mode="code" tag="switchboard" />

`current_result` returns a `CurrentResult` exposing the median `result()` (a `Decimal`) along with `min_timestamp_ms()` and `max_timestamp_ms()`. Unlike Pyth's `get_price_no_older_than`, it does not gate on age, so the consumer checks the timestamps against the clock itself. See the [Switchboard Sui docs](https://docs.switchboard.xyz/product-documentation/data-feeds/sui) for feed creation and the on-demand flow.

## Check for a stale price

The stale-price check is the exported `checkStale` function, a separate code path from the update-and-read flow. It never applies an update. It looks up the feed's existing `PriceInfoObject`, calls the Pyth staleness-checked reader with your `maxAgeSecs`, and runs the transaction through `devInspectTransactionBlock`. It returns an object with the dev-inspect `status` and, when the read aborts, the `error` string. It throws `no PriceInfoObject for feed` followed by the feed ID if the feed has no onchain object.
