Object Display is a way to render any object on Sui using templating syntax. It renders Sui Move object values into human-readable strings, JSON, or encoded representations. A Display object defines a set of key-value pairs where both keys and values are format strings, that is, template strings into which data from an object is substituted when the object is rendered.

Object Display enables onchain management of offchain representation for a type. In other words, the rules for how an object of that type is presented offchain are defined and managed onchain, in a Display object. You can create fully composable and dynamic NFTs by substituting data for an object into a template string.

Check out the [interactive preview application](/develop/objects/display/display-preview) to see how you can use Object Display. The application covers the templating language and includes a visual display builder. 

## What changed in Display V2?

Object Display V2 is the current Object Display standard. The legacy standard, Display V1, used an event-discovery model. V2 replaces it with a registry-backed model, which means each object type `T` has one deterministic `Display<T>` derived from the global display registry and that type. This makes the display for any type predictable: there is exactly one `Display<T>` for each type, and it comes from the registry.

Use the `sui::display_registry` APIs when creating a display from Move code. For legacy displays, use `migrate_v1_to_v2` only if you are explicitly migrating a V1 display that was not already migrated by the system snapshot.

### What features does Display V2 add?

Display V2 brings a richer templating model, improved rendering pipeline, and better tooling, including:

- **Collection access**: Use vectors, sets, and maps directly in your display templates.

- **Dynamic field access**: Reference dynamic fields on objects in your templates.

- **Object loading**: Load and reference objects when resolving display.

- **GraphQL**: Rich APIs to use display as a querying tool, not just for rendering.

## Migrate a V1 display to V2

To migrate a legacy display, call `migrate_v1_to_v2` on the `DisplayRegistry` object and pass the legacy `sui::display::Display` value for your type. The registry address is system-generated at `0xd`. The call returns the new V2 display and its `DisplayCap<T>`:

```move
        let (_display, _cap) = registry.migrate_v1_to_v2(legacy_display, scenario.ctx());
```

Each type has only one V2 display, so a second migration for the same type aborts with `EDisplayAlreadyExists`. To create a V2 display for a type that has no V1 display, call `new_with_publisher<T>` with the package `Publisher` instead:

```move
    let (display, cap) = registry.new_with_publisher<T>(&mut publisher, scenario.ctx());
```
