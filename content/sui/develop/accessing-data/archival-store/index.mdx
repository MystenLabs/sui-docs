## What is the Archival Store and Service?

The Archival Store and Service provide a scalable, consistent foundation for accessing historical onchain data on Sui beyond what full nodes or indexer databases typically retain. Full nodes enforce limited data retention for scalability and performance, so applications that need to query old transactions, checkpoints, or object states rely on the archival infrastructure. You can run the Archival Service yourself as part of a fully self-managed stack, or use the Archival Service and a full node from an RPC provider or indexer operator.

## Do GraphQL and gRPC apps need the Archival Service?

Yes, when they query historical data that full nodes have pruned. This infrastructure serves as the historical backbone for [GraphQL RPC](/develop/accessing-data/graphql/graphql-rpc), [gRPC](/develop/accessing-data/grpc)-based applications, and data platforms, providing efficient point lookups (retrieving an individual transaction, checkpoint, or object state) for historical data even after full nodes have pruned it, that is, removed it under their limited data retention.

## When do you need the Archival Service?

A full node serves ledger history only down to its serving floor. The full node has pruned all data under that floor, and that data is permanently gone from the node. When your request names a lower bound under the serving floor, or covers a checkpoint range that lies wholly under it, the full node rejects the request with `OutOfRange` instead of returning an empty page. When your request has no lower bound of its own, the full node raises the start of the request to the serving floor. Use the Archival Service for any data older than the serving floor of the full node you query.
